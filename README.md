## 1. Что получится в итоге

На вашем компьютере будут работать две программы. Обе запускаются внутри Docker, поэтому ставить
PostgreSQL и Python отдельно не нужно.

- **PostgreSQL 17** с учебной базой `demo` — это [демонстрационная база авиаперевозок
  Postgres Pro](https://postgrespro.ru/education/demodb): аэропорты, самолёты, рейсы, билеты,
  бронирования. Та же база, что на семинарах.
- **Jupyter** — среда, в которой открывается ноутбук с заданием. Запросы пишутся в ячейках ноутбука,
  результат показывается таблицей прямо под ячейкой.

Дополнительно можно поставить **DBeaver** — программу, в которой удобно рассматривать таблицы и
пробовать запросы. Для сдачи задания она не обязательна.

Параметры базы. Они понадобятся в DBeaver; ноутбук подставляет их сам.

| Параметр | Значение |
|---|---|
| Хост | `localhost` |
| Порт | `5432` |
| База данных | `demo` |
| Пользователь | `some-user` |
| Пароль | `some-password` |

База работает только на вашем компьютере и из интернета недоступна, поэтому пароль можно не прятать.

Демобаза загружается без изменений, поэтому её таблицы лежат в схеме `bookings`, и в запросах имя
пишется вместе со схемой: `bookings.flights`. Свои таблицы вы создаёте в схеме `public`:
`public.meals`. Какие в демобазе таблицы и как они связаны, показано на схеме: [`db/schema.md`](db/schema.md).

> На занятиях 3 и 4 мы писали `public.flights`, `public.airports` и так далее. В материалах этого
> репозитория перед таблицами демобазы везде стоит `bookings.` — сами таблицы и данные те же.

## 2. Установите Docker

Docker — программа, которая запускает другие программы в изолированных «контейнерах». Нам она нужна,
чтобы одной командой получить готовую базу с данными.

Найдите раздел для своей операционной системы.

### Windows 10 и 11

1. Откройте страницу <https://www.docker.com/products/docker-desktop/> и нажмите **Download for
   Windows**. Если у вас обычный ноутбук или компьютер, выбирайте вариант **AMD64**.
2. Запустите скачанный файл `Docker Desktop Installer.exe`. В окне установки оставьте галочку
   **Use WSL 2 instead of Hyper-V** и нажмите **OK**.
3. Когда установка закончится, **перезагрузите компьютер**, если установщик об этом попросит.
4. Запустите **Docker Desktop** из меню «Пуск». Примите пользовательское соглашение. Вход в учётную
   запись можно пропустить: **Continue without signing in** или **Skip**.
5. Подождите, пока в левом нижнем углу окна появится зелёная надпись **Engine running**.

Если Docker Desktop пишет, что нужно обновить WSL: нажмите правой кнопкой на кнопку «Пуск», выберите
**Терминал (Администратор)** или **Windows PowerShell (администратор)**, выполните команду ниже
и перезагрузите компьютер.

```powershell
wsl --update
```

Подробная официальная инструкция: <https://docs.docker.com/desktop/setup/install/windows-install/>.

### macOS

1. Узнайте, какой у вас процессор: меню **Apple** в левом верхнем углу экрана → **Об этом Mac**. В строке «Чип» написано **Apple M1**
   (M2, M3…) — у вас Apple Silicon. В строке «Процессор» написано **Intel** — у вас Intel.
2. Откройте страницу <https://www.docker.com/products/docker-desktop/> и нажмите **Download for Mac**,
   выбрав свой вариант: **Apple Silicon** или **Intel Chip**.
3. Откройте скачанный файл `Docker.dmg` и перетащите значок **Docker** в папку **Applications**.
4. Запустите **Docker** из папки «Программы». Разрешите запуск, примите пользовательское соглашение,
   выберите рекомендуемые настройки. Вход в учётную запись можно пропустить.
5. Подождите, пока в левом нижнем углу окна появится зелёная надпись **Engine running**.

Подробная официальная инструкция: <https://docs.docker.com/desktop/setup/install/mac-install/>.

### Linux

На Linux достаточно Docker Engine, без Docker Desktop. Пример для Ubuntu и Debian — откройте терминал
и выполните команды по очереди:

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Вторая команда разрешает запускать Docker без `sudo`. Чтобы она подействовала, **выйдите из системы
и войдите снова** (или перезагрузите компьютер).

Для других дистрибутивов выберите свой на странице <https://docs.docker.com/engine/install/>.

### Проверьте, что Docker работает

Откройте терминал: на Windows — программа **Терминал** или **PowerShell**, на macOS — **Терминал**.
Выполните две команды:

```bash
docker --version
docker compose version
```

Каждая должна напечатать номер версии, например `Docker version 29.6.2` и
`Docker Compose version v5.3.1`. Точные цифры не важны. Если вместо версии появилась ошибка —
загляните в [раздел 8](#8-если-что-то-не-работает).

> **Важно.** На Windows и macOS Docker Desktop должен быть запущен каждый раз, когда вы работаете
> с базой. Если его закрыть, база остановится.

## 4. Запустите базу и Jupyter

### Откройте терминал в папке репозитория

- **Windows 11.** Откройте папку репозитория в Проводнике, нажмите правой кнопкой на пустом месте
  и выберите **Открыть в терминале**.
- **Windows 10.** Откройте папку в Проводнике, щёлкните по адресной строке сверху, наберите
  `powershell` и нажмите Enter.
- **macOS.** Откройте программу **Терминал**, наберите `cd ` (с пробелом на конце), перетащите папку
  репозитория из Finder в окно терминала и нажмите Enter.
- **Linux.** Нажмите правой кнопкой на папке в файловом менеджере и выберите **Открыть в терминале**.

Проверьте, что вы в нужной папке: команда `ls` должна показать файлы `docker-compose.yml`,
`README.md` и папки `week_1` … `week_4`.

### Выполните одну команду

```bash
docker compose up -d
```

Что происходит в первый раз (5–10 минут, зависит от скорости интернета):

1. Docker скачивает PostgreSQL и Python.
2. Скачивает демобазу с сайта Postgres Pro.
3. Запускает PostgreSQL и загружает в него данные.
4. Запускает Jupyter.

Команда закончила работу, когда в конце появились строки:

```text
 Container hse-db-postgres  Healthy
 Container hse-db-jupyter   Started
```

Следующие запуски занимают несколько секунд: всё уже скачано, данные сохранены.

### Проверьте результат

```bash
docker compose ps
```

В столбце `STATUS` у `hse-db-postgres` должно быть `Up … (healthy)`, у `hse-db-jupyter` — `Up …`.

## 5. Откройте ноутбук с заданием

1. Откройте в браузере адрес <http://localhost:8888>. Пароль не нужен.
2. Слева — список папок репозитория. Откройте `week_4`, затем двойным щелчком — `homework_3.ipynb`.
   Задачи семинаров открываются так же: `week_3/classwork_3.ipynb`, `week_4/classwork_4.ipynb`.
3. Выполните первые ячейки ноутбука по порядку: щёлкните по ячейке и нажмите **Shift + Enter**.
4. Ячейка «Проверка подключения» должна показать таблицу из пяти аэропортов. Если показала —
   всё настроено, можно решать задачи.

Как устроен ноутбук:

- Ячейка с запросом начинается со строки `%%sql`. Всё, что написано ниже, отправляется в PostgreSQL.
- **Shift + Enter** выполняет ячейку. Под ней появляется таблица с результатом и число строк,
  а если в запросе ошибка — её текст от PostgreSQL.
- Ноутбук сохраняется сочетанием **Ctrl + S** (на macOS — **Cmd + S**) в ту же папку `week_4`
  на вашем компьютере.

## 6. Подключитесь к базе через DBeaver

DBeaver — бесплатная программа для работы с базами данных. В ней удобно посмотреть список таблиц,
их столбцы и данные, а также быстро попробовать запрос, прежде чем переносить его в ноутбук.

### Установка

Скачайте **DBeaver Community** со страницы <https://dbeaver.io/download/> — выберите установщик для
своей системы (Windows, macOS для Apple Silicon или Intel, Linux) и установите как обычную программу.

### Создание подключения

База должна быть запущена ([раздел 4](#4-запустите-базу-и-jupyter)).

1. В меню выберите **Database → New Database Connection** (в русском интерфейсе —
   **База данных → Новое соединение**).
2. В списке выберите **PostgreSQL** и нажмите **Next** (**Далее**).
3. Заполните поля:

   | Поле | Значение |
   |---|---|
   | Host (Хост) | `localhost` |
   | Port (Порт) | `5432` |
   | Database (База данных) | `demo` |
   | Username (Пользователь) | `some-user` |
   | Password (Пароль) | `some-password` |

4. Нажмите **Test Connection…** (**Тест соединения…**). В первый раз DBeaver предложит скачать
   драйвер PostgreSQL — нажмите **Download** (**Скачать**).
5. Должно появиться окно **Connected** (**Соединено**). Нажмите **OK**, затем **Finish** (**Готово**).

### Где смотреть таблицы и писать запросы

- Слева, в панели **Database Navigator**, раскройте: **demo → Databases → demo → Schemas → bookings →
  Tables**. Таблицы, которые вы создадите сами, появятся рядом, в схеме **public**. Двойной щелчок по таблице открывает её: вкладка **Properties** — столбцы и типы,
  вкладка **Data** — строки.
- Чтобы написать запрос, нажмите правой кнопкой на подключении **demo** и выберите
  **SQL Editor → New SQL script** (**Редактор SQL → Новый скрипт SQL**). Запрос выполняется
  сочетанием **Ctrl + Enter** (на macOS — **Cmd + Enter**).

> **Про время.** DBeaver показывает дату и время в часовом поясе вашего компьютера, а ноутбук —
> в московском, как задано в базе. Если вы не в московском поясе, один и тот же запрос с отбором
> по дате может вернуть в DBeaver немного другое число строк. Для сдачи важен результат в ноутбуке.

Ноутбук и DBeaver работают с одной и той же базой: таблица, созданная в ноутбуке, видна в DBeaver,
и наоборот. Чтобы увидеть новую таблицу в списке, нажмите правой кнопкой на **Tables** → **Refresh**
(**Обновить**).

## 7. Каждый день: остановить, запустить, сбросить

Все команды выполняются в терминале, открытом в папке репозитория.

| Что нужно | Команда | Что происходит |
|---|---|---|
| Остановить | `docker compose down` | База и Jupyter останавливаются. Данные и ваши таблицы сохраняются |
| Запустить снова | `docker compose up -d` | Всё поднимается за несколько секунд в том же состоянии |
| Проверить состояние | `docker compose ps` | Показывает, какие контейнеры работают |
| Сбросить базу | `docker compose down -v`, затем `docker compose up -d` | База создаётся заново из демобазы |

> **Осторожно со сбросом.** Команда `docker compose down -v` удаляет все таблицы, которые вы создали
> сами, и возвращает демобазу в исходное состояние. Файлы ноутбуков при этом не затрагиваются.

После перезагрузки компьютера: запустите Docker Desktop (Windows, macOS), дождитесь надписи
**Engine running** и выполните `docker compose up -d`.

Если в репозитории появились новые задания: скачайте их (`git pull` или заново архивом) и выполните
`docker compose up -d --build`.

## 8. Если что-то не работает

Найдите свою ошибку в списке. Если её нет или совет не помог — напишите семинаристу на
`foxleren@yandex.ru`: приложите текст ошибки целиком и укажите операционную систему.

**`docker: command not found` или «docker не является внутренней или внешней командой».**
Docker не установлен или терминал открыт до установки. Закройте терминал, откройте заново. На Windows
и macOS убедитесь, что Docker Desktop запущен.

**`Cannot connect to the Docker daemon` или `error during connect … dockerDesktopLinuxEngine`.**
Docker Desktop не запущен. Запустите его и дождитесь надписи **Engine running**.

**На Linux: `permission denied while trying to connect to the Docker daemon socket`.**
Вы не вышли из системы после команды `sudo usermod -aG docker $USER`. Выйдите и войдите снова.

**`no configuration file provided: not found`.**
Терминал открыт не в папке репозитория. Вернитесь к началу [раздела 4](#4-запустите-базу-и-jupyter).

**`ports are not available` или `address already in use`, в тексте есть `5432`.**
Порт занят — скорее всего, на компьютере уже установлен свой PostgreSQL. Откройте файл `.env`
в любом текстовом редакторе, замените `POSTGRES_PORT=5432` на `POSTGRES_PORT=5433`, сохраните
и снова выполните `docker compose up -d`. В DBeaver в поле «Порт» тогда пишите `5433`. В ноутбуке
ничего менять не нужно.

**То же самое, но в тексте есть `8888`.**
Порт занят другим Jupyter. В файле `.env` замените `JUPYTER_PORT=8888` на `JUPYTER_PORT=8889`,
выполните `docker compose up -d` и открывайте в браузере <http://localhost:8889>.

**Ошибка при первом запуске со словами `edu.postgrespro.ru`, `failed to load cache key`
или `failed to resolve source metadata`.**
Не удалось что-то скачать. Проверьте интернет, выключите или, наоборот, включите VPN и повторите
`docker compose up -d` — загрузка продолжится с того места, где оборвалась.

**Ноутбук пишет «НЕ УДАЛОСЬ ПОДКЛЮЧИТЬСЯ К БАЗЕ».**
База не запущена. Выполните `docker compose ps`: если `hse-db-postgres` в списке нет или у него нет
пометки `healthy`, выполните `docker compose up -d`.

**Страница <http://localhost:8888> не открывается.**
Выполните `docker compose ps`. Если `hse-db-jupyter` в списке нет — выполните `docker compose up -d`
и прочитайте, что написано в конце вывода.

**`ОШИБКА: relation "…" already exists`.**
Это не поломка: таблица с таким именем уже создана, например при прошлом запуске ячейки. Удалите её
командой `DROP TABLE public.имя_таблицы;` и выполните ячейку заново.

**На Linux: ноутбук не сохраняется или появились файлы, которые нельзя удалить.**
Jupyter в контейнере работает от имени администратора, и созданные им файлы принадлежат ему.
Верните себе права командой `sudo chown -R $USER .` в папке репозитория.

**Всё запуталось, хочу начать с чистого листа.**
Выполните `docker compose down -v`, затем `docker compose up -d --build`. База будет создана заново.

## 9. Запасной путь: Jupyter на своём Python

Этот раздел — только для тех, у кого уже установлен Python 3.10 или новее и кто хочет запускать
Jupyter без Docker. База в любом случае работает в Docker.

1. Поднимите только базу:

   ```bash
   docker compose up -d postgres
   ```

2. В папке репозитория создайте окружение и установите библиотеки.

   macOS и Linux:

   ```bash
   python3 -m venv .venv
   .venv/bin/pip install -r jupyter/requirements.txt
   .venv/bin/jupyter lab
   ```

   Windows (PowerShell):

   ```powershell
   py -m venv .venv
   .venv\Scripts\pip install -r jupyter\requirements.txt
   .venv\Scripts\jupyter lab
   ```
